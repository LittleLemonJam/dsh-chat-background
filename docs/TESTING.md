# 测试指南

> 测试分层、如何运行、如何新增断言，以及端到端测试的前置条件与排障。
> 相关：[DEVELOPMENT.md](DEVELOPMENT.md) · [ARCHITECTURE.md](ARCHITECTURE.md) · [CONVENTIONS.md](CONVENTIONS.md)

## 1. 测试分层

| 层       | 命令                   | 覆盖                                                                                                                                  | 是否需要 DSH |
| -------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| 格式     | `npm run format:check` | 缩进/引号/分号/行宽/Markdown 表格                                                                                                     | 否           |
| 静态检查 | `npm run check`        | 清单字段、locale、构建产物新鲜度、编码/换行、i18n 键、遗留标记                                                                        | 否           |
| 单元测试 | `npm run test:unit`    | 宿主路由（成功/404/405/403/304/HEAD）、图片名校验、目录清单、token 汇总、格式化/颜色/滑杆工具、i18n 键                                | 否           |
| 端到端   | `npm run test:e2e`     | 真实 DSH Web 实例里的背景、侧栏、背景条、进度条、Token 行、背景/UI 两个标签页、开关/滑杆/调色盘、深色主题、语言切换、resize、宿主路由 | 是           |

CI（`.github/workflows/ci.yml`）在 ubuntu（Node 22/24）与 **Windows（Node 24）** 上跑格式、构建、静态检查与单元测试；
端到端因为需要本机 DSH 安装与浏览器，只在本地运行。

## 2. 端到端测试

### 2.1 前置条件

1. 本机已安装 DSH 桌面端（`>= 0.2.1-rc.3`）；
2. 有 Edge 或 Chrome；
3. 工具能定位到 DSH CLI：
   - 默认尝试 `dsh`（PATH）、环境变量 `DSH_CLI`，或 `--dsh <path>` 显式指定；
4. 工具能定位到浏览器：默认尝试常见 Edge/Chrome 路径、`DSH_E2E_BROWSER`、`--browser <exe>`。

### 2.2 运行

```bash
npm run test:e2e                     # 全部套件（跳过 00- 开头的调试探针）
npm run test:e2e -- --suite 01-smoke # 只跑一个套件
npm run test:e2e -- --keep           # 保留临时 DSH_HOME 与产物，便于排查
```

运行过程：

1. 在 `.tmp/e2e-home/` 生成隔离的 `DSH_HOME`（**不会**碰用户 `~/.dsh`）与 profile `e2e`；
2. 复制本插件的运行时文件、写入 `~/.dsh/backgrounds` 同级的样例图片；
3. 用独立端口启动一个 DSH Web 实例（`--no-open`），从输出解析带 token 的 URL；
4. 逐个套件用无头 Edge/Chrome + CDP 执行步骤；
5. 结束（或失败）时杀掉实例、删除临时 home；`--keep` 时保留，产物始终保留。

### 2.3 产物

```text
.tmp/e2e-artifacts/
├─ summary.json           每个套件的状态与产物目录
└─ <suite>/
   ├─ report.json         页面事实、逐步日志、断言结果、控制台错误、截图
   └─ *.png               截图
```

产物按套件保留（重复运行只覆盖对应套件目录），全量运行的 `summary.json` 可作为发版证据；
`report.json` 中的实例 token 已脱敏为 `token=…`。`.tmp/` 已被 git 忽略，不会进入仓库。

`report.json` 的 `checks[]` 是断言明细；`facts` 是终态 DOM 快照（背景标记、变量、背景条几何、Token 文本、
设置行标题等），排查回归时先看它。

### 2.5 新增断言

步骤是 JSON 数据，不是脚本。常用步骤：

```json
{ "wait": 12000 }
{ "clickText": "继续", "tag": "button" }
{ "click": "[aria-label=\"账号菜单\"]" }
{ "eval": "document.title" }
{ "check": "可读的断言说明", "expr": "(() => { ... return true })()" }
{ "shot": "my-screenshot" }
```

- `check` 的 `expr` 必须返回 `true` 才算通过；可以是 `(async () => { ... })()`。
- 断言的 `label` 用中文写清「期望什么」，失败时 `report.json` 会带表达式返回值。
- 控制台错误默认视为失败；确有噪声时在套件顶层加 `"allowConsoleErrors": ["忽略片段"]`。
- 步骤里不要写注释（JSON 不支持），用 `{ "log": "..." }` 做进度标记。

### 2.6 排障

| 现象                                   | 处理                                                                          |
| -------------------------------------- | ----------------------------------------------------------------------------- |
| `could not locate the DSH CLI`         | 传 `--dsh <dsh 可执行文件>` 或设 `DSH_CLI`                                    |
| `devtools endpoint never became ready` | 浏览器路径错误或被占用；传 `--browser`；确认没有同 user-data-dir 的残留进程   |
| 套件超时                               | 默认 10 分钟/套件；首次启动较慢可先单独跑 `--suite 01-smoke --keep` 观察      |
| 页面显示 `Failed to load plugins`      | 客户端 bundle 抛错；看上一条控制台错误，通常是 free variable 或 hook 用法问题 |
| 找不到 `继续`/`新会话` 按钮            | DSH 版本 UI 变化；先用 `01-smoke` 的日志观察按钮清单再改选择器                |

## 3. 单元测试

- 位置：`test/unit/*.test.mjs`，用 Node 自带 `node:test` + `assert/strict`，无第三方依赖；当前 **78** 个用例。
- 只测试纯逻辑：通过 `import` 直接引用 `host/*.js`、`src/lib/*.js`、`src/i18n.js`（这些模块在导入期不碰 DOM）。
- 临时文件一律放 `os.tmpdir()` 并用 `mkdtemp`，测试结束 `rm` 清理。
- 宿主路由用 `Writable` 伪造 Node response，覆盖成功、HEAD、304、404、405、403 与缓存窗口。

## 4. 手工验收清单（发版前）

- [ ] 设置 → 页面设置：背景标签 6 行、UI 标签 3 组卡片，顺序与控件类型正确；
- [ ] 选择背景图后：整窗透出图片；左侧栏/主窗口/文字框/右侧栏遮罩分别生效；设置面板保持不透明；
- [ ] 四个遮罩滑杆互不影响（0 全透明、100 不透明）；开启「遮罩层设置跟随深浅色」后，浅色/深色各存一套值；
- [ ] 背景/UI 标签切换正常，UI 下三组设置分别在同一边框卡片内；
- [ ] 背景条：宽度等于输入卡片、覆盖用量行；行变高/变宽时跟随；
- [ ] 进度条：空闲时隐藏；运行中不为 100% 且有脉动；关闭开关即消失；
- [ ] Token 行：位于账号行上方，文本形如 `Token总用量：438M`，悬停显示精确值与会话数；
- [ ] 深色主题下背景条默认色为深色；两个颜色「恢复默认」回到主题默认；
- [ ] 切到英文后行标题为英文；切回中文正常；
- [ ] 刷新页面后所有设置恢复；
- [ ] 控制台无错误；卸载/禁用插件后页面恢复原样（无残留属性/节点）。
